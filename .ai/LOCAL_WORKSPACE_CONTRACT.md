# Local workspace and official-source calibration contract

Date: 2026-10-05 JST. Status: implementation contract for the user's newly authorized local storage and full-variant enrichment scope; implementation and live calibration results are not established by this document.

## Authority, outcome and acceptance boundary

The user requests that all 27,046 currently registered Kiwa variants be made calibrated/editor usable, has no measurements or Supabase account, and authorizes saving Parts, images and Designs on this PC with later Supabase migration. This supersedes only the prior no-local-domain-persistence clauses in HANDOFF, CATALOG_CONTRACT and PART_REGISTRATION_CONTRACT. Their source integrity, missingness, network policy and draft/domain separation rules remain in force. Existing source inventory under `.local/catalog/` and `.local/parts/` is user data and must be preserved.

Implement an actual local calibrated Part/Asset/Design backend and run official-source enrichment against every existing variant. A completed attempt is not a completed calibration. Full requested calibration is achieved only when all 27,046 entries pass evidence and domain validation; otherwise report exact ready/blocked/failed/pending counts, reason coverage and remaining source limitations. A technically complete backend or all-green fixtures cannot prove all real variants usable. No assumption that official pages contain every required dimension is permitted.

`RegisteredPartDraft` remains inventory metadata. An eligible, validated promotion produces a genuine domain `Part` plus immutable image asset and evidence; blocked drafts never enter editor pickers. Existing manual measured calibration remains available locally. Automated official-source evidence does not certify actual-product ±3% physical accuracy without independent physical evidence.

## Local persistence and identity

- Fixed root: `.local/workspace/` resolved from the trusted project root on the Node server. It contains persistent PGlite `database/`, bounded `staging/`, and `exports/`. Browsers select domain IDs only, never filesystem paths. Reject path traversal, absolute/UNC paths, symlink/reparse escapes and noncanonical identifiers; do not permit configurable request-selected roots.
- Use already installed `@electric-sql/pglite` in the Node server, backed by `.local/workspace/database/`. Reuse all 16 existing migrations unchanged, with a narrowly scoped local bootstrap for SQL roles, `auth` and `storage` schemas based on `src/services/storage.test.ts`. Retain a migration ledger with ordered filename/hash/schema version and reject hash mismatch or unsupported schema. Local-specific workspace metadata, byte storage, jobs/certificates/mappings and idempotency records live in a separate local schema; they do not redefine cloud migration semantics.
- A bootstrap transaction creates a durable workspace owner UUID and matching local-only `auth.users` row; both must agree on reopen. This UUID is the SQL owner; browser/session/recovery identity is `local:<UUID>`, never a fabricated cloud account. Domain records retain UUID IDs and existing SQL ownership columns. A restored backup preserves identity; a deliberately separate workspace gets another identity. Missing metadata beside existing domain rows is corruption, not permission to mint another owner or reset data.
- Local `auth.uid()` may read a server-controlled transaction-local setting as the existing fixtures do. This is an internal SQL compatibility shim, not an issued JWT, cloud login or authentication claim supplied by the browser. Derive the owner from persisted trusted workspace identity, set it with transaction-local scope, execute domain operations under `authenticated` SQL role and reset state automatically at transaction completion. Expose neither SQL execution nor caller-selectable owner/role/config settings.
- Acquire a cross-process exclusive workspace lock before opening PGlite and hold it until the sole server instance closes the DB; a JavaScript singleton alone is insufficient. Queue the instance's DB transactions, reads included where session role/settings could interleave. A second process returns `WORKSPACE_BUSY` without opening the files. Stale recovery must prove the previous owner exited; never steal a live lock based only on elapsed time. Network/image preparation is outside SQL transactions; commit rechecks current evidence/reference/revision state.
- SQL transactions are the sole domain commit point. Reserve asset IDs/paths, insert storage-object metadata and validated bytes, call existing Part/Design RPC functions, write source mappings/certificates/idempotency results and commit together. Store original/high/medium/thumbnail and optional segment bytes in a local `bytea` table keyed to the corresponding `storage.objects` identity/path, with length/MIME/SHA-256. A metadata object cannot satisfy upload completeness without actual validated bytes: local trigger/FK constraints enforce one matching byte row before asset commit. Local byte updates are forbidden; delete cascades only through SQL cleanup permitted by existing reservation policies. No separate filesystem blob or custom JSON manifest transaction layer.
- Return success only after the actual SQL commit and required persistent flush completes. Verify Windows disk-backed PGlite reopen after graceful restart and hard process interruption; do not promise power-loss durability beyond confirmed runtime/filesystem support. Failed transactions roll back aggregate sections, revisions, assets, byte rows, reservations and mappings together. Restart checks migration ledger, workspace identity and referenced byte hashes; corruption fails visibly without empty reset. Recovery from validated backup is explicit. Cleanup cannot touch existing `.local/catalog/` or `.local/parts/`.
- Idempotency keys scoped to workspace and operation prevent lost-response upload/promotion/create retries from creating duplicate visible records. Stored keys bind the exact request digest; reused keys with different payloads fail. Concurrent successful Design saves increment their revisions once each.

## Security and server interfaces

Use the Node runtime, loopback listener and existing `src/server/localCatalogAccess.ts` control boundary for a fixed `/api/local/workspace/*` family, strengthening the shared helper where necessary. All local data, original images and exports are private to this local deployment. Validate loopback Host, served authority, same-origin Origin when present and Fetch Metadata; require a fresh non-guessable same-session token and exact same-origin Origin for every mutation, upload, import/export creation and state-changing worker control. Do not trust forwarded host/IP headers. Binding a non-loopback listener is unsupported and must fail closed, even if a caller supplies a forged loopback Host. The token/bootstrap endpoint has identical read restrictions, no permissive CORS and no caching. Missing optional browser headers do not weaken mutation checks. Resource reads cannot expose arbitrary filesystem content; use validated IDs and owner-checked SQL asset/object lookup, safe raster MIME and no-store/private responses. Follow the existing approved token strategy for image URLs without putting persistent secrets into portable manifests or logs.

Validate complete request schemas, sizes, finite numeric values and ownership server-side. Reject undeclared fields where accepting them could alter identity/revision/path/security semantics. File uploads have explicit per-file/total bounds, raster decoding limits and SHA-256 verification; no HTML/SVG execution. Trusted local mode does not bypass cloud authentication, source-fetch protections or server-side geometry checks. No anonymous cloud RPC/storage fallback.

## Shared repository and asset contracts

Introduce a narrow backend-neutral transport and workspace session/context supplying `kind`, owner identity, capabilities and an epoch. Existing repository row/payload mapping is retained: cloud adapter invokes authenticated Supabase, local adapter invokes allowlisted same-origin operations that execute the same SQL RPC functions/queries. A small typed RPC/query operation surface is sufficient; do not emulate arbitrary Supabase/PostgREST query strings, invent a JWT, or duplicate the repository SQL rules. Local adapters call protected endpoints; no browser filesystem API or direct `.local` import. Absence of Supabase configuration selects/explains local mode. When cloud is configured, explicit mode selection is stable for the edit session; local failures never fall back to cloud or vice versa. A Design URL includes or unambiguously resolves backend context, preventing UUID collisions from opening another backend's record.

Contracts cover Part list/get/save/archive/remove-if-unreferenced/user state/source snapshot; Design create/list/get/save; asset get-metadata/resolve-image/read-original/savePart/cleanup; session owner/capability changes. Replace direct `.from(...)`, `.rpc(...)` and auth dependencies in PartRegistration, PartEdit, source refresh, library, Designs and DesignEditor. Cloud adapter retains auth-change invalidation, private signed URLs and owner checks. Backend/workspace/auth changes increment epoch, clear stale images/unsaved state and invalidate in-flight operations; stale successful responses cannot replace another owner's editor.

Local assets store exact `original`, `high`, `medium`, `thumbnail` bytes and, when required, four `path_segment` variants in SQL `bytea` rows. Keep domain `ImageAssetInput` metadata, positive pixel dimensions/mmPerPx and source transform; `contentHash` retains existing meaning as normalized-high hash. Add per-file hashes/length/MIME in local byte metadata, not a redefinition of that domain field. New image bytes create a new immutable Asset ID. Validate decoded size and geometry/calibration consistency, complete four-file presence, asset kind and local owner before Part commit. Original must remain the imported original bytes, including after re-edit; source-transform metadata preserves crop/rotate/mask/calibration provenance. Deleting/cleanup cannot remove assets referenced by committed Parts, pending committed operations or segment specs.

Server validation executes the actual existing migrations/RPC constraints, including 002, 009 and 014–016, rather than reimplementing a handwritten parity validator. Keep existing client TypeScript geometry validation for immediate feedback, and validate transport schema/asset decoding/hash/certificates on the server. SQL remains authoritative for enums, positive required node dimensions, nullable patch/omitted section semantics, CP/Hole definitions, purchase constraints, path render/segment dependencies, compatibility configuration, referential ownership, revisions and geometric/attachment/mirror invariants. Preserve unknown optional physical dimensions; unknown compatibility remains unknown rather than manufactured compatible. Reuse existing PGlite SQL negative fixtures against the persistent local wrapper.

Part editing follows existing `save_part_successor`: update an unreferenced Part in place; editing any Part referenced by a committed Design creates a successor, copies omitted sections, records `supersedesPartId`, generates/remaps owned definition IDs as needed and archives the previous entry as the cloud flow does. Existing Designs retain old Part/Asset/definition IDs and byte-identical images. Archive retains referenced records; removal is only for unreferenced records. A save racing a new Design reference is serialized and reevaluates reference state inside the same transaction. Source refresh never mutates calibrated geometry by itself.

Design creation produces the existing empty aggregate and revision semantics. Save requires complete sections, exact Design identity/type, valid local-owned Parts/assets and all geometric/attachment/mirror invariants. Compare `expectedRevision` and increment once under the writer lock; return `REVISION_CONFLICT` without replacing any section. Explicit existing force-overwrite UX may bypass only the revision comparison, never ownership/schema/geometry checks. Archived Parts are usable only for already committed entity+Part pairs, matching cloud rules. Timestamps/revision are server-controlled. Picker excludes archived/unready entries but loads archived references for existing Designs.

Recovery remains a separate IndexedDB safety snapshot, keyed by backend-scoped owner plus Design ID. Local identity survives server restart; cloud account and workspace identities cannot see each other's recovery. Capture aggregate/revision/owner/epoch atomically, preserve newest edit generation, and clear only the saved captured revision after acknowledgement. Use neutral persisted-save naming instead of falsely labeling a local save cloud. Browser offline signals cannot prohibit loopback saves if the local server is reachable; server unreachable leaves recovery available without reporting durable server success.

## Official-source enrichment and calibration gate

Run one resumable supervised worker with the catalog policy/public-resource restrictions, single remote request pacing, bounded resources and durable checkpoints. Seed exact provider/product/variant keys and catalog hash from the 27,046 existing drafts; do not merge duplicate SKUs, unavailable variants or options. Recheck robots/provider policy before requests, retain raw bounded snapshots, original/final URLs, timestamps, parser version and hashes. Detail-page/official diagram or approved official document enrichment is permitted only within verified policy and fixed allowlisted endpoint/host shapes. Captcha, connection-verification page, robots denial, security error and 403/429/5xx halt visibly without bypass or guessed alternate private endpoint. A policy/guard failure can mark dependent variants blocked while stopping network work; it is never ordinary successful page content.

Each variant has evidence-level fields and an explicit status: pending, processing, ready, blocked or failed. `blocked` has machine-readable reasons including missing labeled dimension, ambiguous axis, missing exact-variant image, perspective/scale mismatch, unresolved segment geometry or missing source permission. Reset interrupted processing to pending only on verified worker recovery. Attempts are idempotent and retain previous evidence/corrections. Totals must partition the baseline identity set exactly; discovery of new variants is a separate refresh scope, never silently changes the 27,046 denominator.

Automatic promotion requires all of:

1. Official evidence assigns the physical measurement and image to this exact variant, or explicitly states a shared dimension/geometry/photo correspondence valid for all mapped variants. Product-level galleries, matching names/SKUs and variant-image fallback alone are insufficient.
2. The physical length has explicit unit/axis/feature semantics, no conflict or approximation substituted as exact. Unlabeled `6mm`, `0.6×3mm`, supplier size codes, sale length/weight and pack counts cannot become orthogonal image dimensions. Retain field provenance and known uncertainty.
3. A measurement-to-image correspondence specifies reproducible pixel endpoints/outline, exact source-image hash, visible physical feature, orientation/projection and transform. A printed scale/dimension diagram with known feature mapping can support calibration; an unscaled lifestyle photograph cannot. Generated foreground extraction is only a recorded image-processing result, never proof that the selected silhouette represents measured physical extent. Reject perspective distortion or inconsistent independent axes; do not stretch an image to make unsupported dimensions agree. Existing perspective/calibration rules and numeric thresholds remain unchanged.
4. Domain Part validation succeeds with complete image assets and the verified geometry type. Node width/height derive from validated normalized image extent and calibration, not copied unlabeled options. Automated CP/Hole coordinates, direction, diameter and mechanical ports require their own image/diagram/measurement evidence. Empty definition arrays represent unavailable connection features, not evidence of physical absence; placement-only usability and connection readiness are shown separately. Unsupported connection metadata is not synthesized merely to make attachment actions available. Path parts require evidenced diameter/render/segment physical semantics; chain sales length does not certify link geometry.
5. A durable promotion certificate records all used evidence, algorithm/version, transforms, required validation outcomes and variant mapping. Map draft identity to committed Part only in the transaction that commits the complete asset/Part. A later changed source creates new observations and an explicit successor/promotion workflow, never invalidates historic byte identity silently.

No generic automated segmentation/calibration shortcut is required without a certifiable source fixture. Begin with a bounded live official-source sample to establish actual patterns, then implement only deterministic evidenced patterns and attempt the full inventory. When no pattern establishes correspondence, all affected entries remain blocked. User has no measurements; report required missing provider evidence specifically rather than inventing measurements or repeatedly asking for them.

## Portable backup and future cloud migration

Provide versioned semantic JSON export/import containing domain SQL rows/aggregates, workspace identity, source snapshots, promotion certificates and every referenced original/high/medium/thumbnail/segment byte as canonical base64 with length/MIME/SHA-256. It is not a raw PGlite directory copy or arbitrary SQL dump. Export reads one consistent SQL transaction snapshot; retain IDs/revisions/successors/entity references, source mappings, format/domain/parser versions, migration hashes and exact counts. Exclude tokens, sessions, locks, absolute machine paths and credentials. Record explicit package limits and a `limited` result if exceeded; never silently truncate. A bounded package can cover a selected Design and its dependency closure or a selected Part batch; multiple packages share export-set/workspace identity and item hashes for later migration. Do not assume the entire 27,046-image library fits one in-memory JSON document.

Validate import fully in bounded staging before visible changes: reject unsupported schemas, malformed/noncanonical base64, oversized decoded bytes or entity counts, duplicate IDs/asset paths, missing/hash-mismatched bytes, foreign ownership inconsistencies and dangling/cyclic prohibited references. Paths are semantic reserved-storage identifiers validated by schema, not filesystem targets. Perform the final import using a trusted local-only SQL import operation and one SQL transaction; preserve validated IDs, timestamps/revisions and dependency order while retaining SQL checks/triggers and complete asset reservation/byte/object rules. Do not disable triggers or apply arbitrary package SQL. Match package owner to restored workspace identity; same-identity identical import is idempotent and conflicts fail without overwrite. A different-identity package can initialize a separately controlled empty workspace through an explicit restore operation or fails, never silently relabels existing ownership. Partial batches may reference only dependencies already verified in the target; otherwise reject. Any failure leaves the current workspace unchanged.

Migration readiness means the package is portable and relationships are reconstructible, not that cloud upload succeeded. Specify a mapping manifest keyed by source workspace+Part/Asset/Design/entity IDs to future authenticated cloud IDs and reserved Storage paths, preserving hashes and successor/attachment references. Future migration uses authenticated cloud APIs, validates user ownership and live schema, uploads exact bytes, imports Parts in dependency order and remaps all definition/entity/design references atomically per cloud operation, with resumable checkpoints and response-loss reconciliation. Source local revisions stay in migration provenance; cloud revisions follow cloud save semantics. Record an entry migrated only after authenticated read-back verifies mappings, all references and image hashes. Local records remain intact. This work implements portable export/import and mapping format; actual Supabase migration cannot be executed or reported complete without the future account/connection and external-action authorization.
