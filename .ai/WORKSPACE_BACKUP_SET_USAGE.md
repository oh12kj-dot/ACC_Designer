# 端末保存のバックアップ・復元

`/designs` の「バックアップを書き出す」で、保存済みの全Part・元画像と各サイズの画像・Design・アーカイブ/後継関係を1ファイルに保存する。容量の大きいライブラリも小分けに処理し、ブラウザーのダウンロード機能で保存する。旧形式の128MB上限はこの新形式の全体容量には適用しない。1画像20MiB・1記録32MiBの上限と、保存先のディスク空き容量は必要。

掲載情報の比較証拠がある場合は、証拠と検証に必要な出典情報も自動で同梱します。復元後も当時の掲載差分・購入保留を保持します。これは取得時点の記録であり、最新価格・在庫の確認ではありません。証拠が壊れている場合は書出しを中止します。比較証拠がない場合は従来形式で書き出し、旧バックアップも読み込めます。新しい証拠付きバックアップの復元には、この機能を含む同じ版のアプリが必要です。

収集カタログ・登録候補・画像審査の作業ファイル（`.local/catalog`、`.local/parts`、`.local/calibration`）は含まれない。公式データを使う端末への移行では、これらの元資料と固定販売方針も従来通り別途保持・配置する。掲載比較に用いた出典情報だけでは元資料の代わりにならない。ログイン情報や端末ロックは含まない。Supabaseへの移行は実行しない。

復元は同じ版のアプリを用意し、アプリを停止した状態で実行する。

復元コマンドのためにNext.jsを起動したりビルドしたりする必要はない。現行の保存・紐・デザイン検証に必要な固定のローカルソースと参照データを読み込み、一時runtimeは終了時に片付ける。アプリ本体と復元スクリプトは同じ版を使う。

```powershell
npm.cmd run workspace:restore -- "C:\backup\accessory-workspace.accbackup.ndjson"
```

復元先はこのアプリの `.local/workspace`。既存フォルダーがある場合は拒否し、上書き・自動移動しない。必要な既存データを保全してから、復元先が存在しない状態で使う。正常な全記録・画像・参照・件数・ハッシュを検証し、完了した保存先だけを公開する。失敗した復元を現在の保存先として使わない。旧JSONバックアップも同じコマンドで復元でき、旧形式には128MB上限が残る。

完了した書出しファイルはブラウザーの保存先に加え、端末の `.local/workspace/exports` に保持する。アプリは完了したバックアップを自動削除しない。書出しが異常終了した一時ファイルは、元の処理の終了と所有する記録を確認できた場合だけ次の起動時に削除する。

実ライブラリへの復元や追加登録は今回実行していない。実機iPhone、電源断、実Supabase移行の受入は別途必要。
