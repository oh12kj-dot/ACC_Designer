# Workspace backup set v2 — proposed implementation contract

Date: 2026-10-16 JST. Status: adoption-ready design proposal; no source changes or real-data operations authorized by this document. This is one coherent extension of the portable-backup section in LOCAL_WORKSPACE_CONTRACT.md. Actual Part registration remains PAUSED; actual Supabase operations remain out of scope.

## Scope and preserved behavior

Back up every row in the existing `portableTables` allowlist, all `storage.objects` and all `local_blobs`, including archived Parts, successors, source snapshots and complete Design aggregates. Preserve owner UUID, row IDs, timestamps, revisions, semantic asset paths, exact image bytes and source-to-target identity (`targetId:null`, migration status `not_migrated`). Never overwrite or merge an existing differing workspace. A full semantic domain-library backup is distinct from the raw collected catalog/draft registry and calibration sidecar files under `.local/catalog`, `.local/parts` and `.local/calibration`: these remain separately retained and are explicitly listed as excluded in the manifest/UI. Do not claim those filesystem sources or a complete machine backup are included. Domain source snapshots already in the database are included. Do not add credentials, token/session/lock/idempotency state, machine absolute paths, or executable SQL to the format.

Version 1 stays supported under its existing size bounds. Version 2 supplies complete-library export plus offline restore; selected subsets, online v2 import, append/merge, cloud import and ownership remapping are out of scope. No real registration is needed to exercise this feature.

## Exact set format

A set is one UTF-8 NDJSON file with extension `.accbackup.ndjson`, no BOM, exactly one JSON object per LF-terminated line. JSON encoding is the existing `JSON.stringify` convention, with no pretty printing; finite numbers only. Hash the exact UTF-8 bytes of `JSON.stringify(record.payload)`; restore recomputes from the parsed payload in its received property order, retaining the version-1 convention. Integrity is accidental-corruption detection, not a signature or hostile-party authentication claim.

1. Header: `{kind:"header",payload:{format:"acc-workspace-backup-set",version:2,exportSetId:<UUID>,owner:<UUID>,migrationHash:<SHA256>,tables:[<exact portableTables order>],createdAt:<ISO>,scope:"full-domain-workspace",migrationStatus:"not_migrated",excluded:[<fixed exclusions above>],limits:{maxLineBytes:33554432,maxBlobBytes:20971520,maxRowsPerChunk:256}},sha256:<payload hash>}`. Reject unsupported version/schema, foreign or malformed owner, unexpected table names/order or limits larger than the supported ceilings. Versions/schema describe actual persisted semantics; do not invent a parser version absent from the source data.
2. Zero or more chunk records, globally contiguous sequence starting at 0: `{kind:"chunk",sequence:<integer>,payload:<payload>,sha256:<payload hash>}`. Row payload: `{type:"rows",table:<allowlisted name>,rows:[...]}`. Object rows use `table:"storage.objects"`. Blob payload: `{type:"blob",path:<semantic path>,mime:<allowed raster>,sha256:<decoded hash>,length:<decoded integer>,body:<canonical base64>}`. One blob per chunk. Every record obeys the 32 MiB encoded-line cap; every blob obeys the existing 20 MiB decoded/per-raster restrictions. Reject a single row exceeding the cap rather than truncate. Batches contain 1..256 rows and shrink before the line ceiling.
3. Footer: `{kind:"footer",payload:{exportSetId:<same UUID>,headerSha256:<header hash>,chunkCount:<integer>,chainSha256:<digest>,counts:{<each table>:<row count>,"storage.objects":<count>,"local_blobs":<count>},blobBytes:<decimal integer string>,complete:true},sha256:<payload hash>}`. Initialize chain to the header hash. For each chunk compute `SHA256(previousChain + "\n" + decimalSequence + "\n" + chunkPayloadHash)`, using ASCII lowercase hexadecimal. Require one footer, end of file immediately thereafter, matching counts/chain/set/header, no blank/extra lines and final LF. Missing, repeated, reordered, substituted or appended chunks fail.

Tables appear in header order, then storage objects, then blobs. Rows within each table are ordered by its actual primary key (part_user_state uses part_id); objects by ID, blobs by path. Validate monotone unique keys and semantic path uniqueness with bounded cursor state and/or staging SQL indexes. All counts use checked safe integers; decoded byte totals use bigint/decimal strings. Remove the artificial whole-set 50,000-row and 90/128 MiB limits only for v2. Per-record limits remain mandatory. There is no finite whole-library RAM allowance masquerading as full-library support; disk capacity is a visible operational limit, and any shortage fails without publishing a complete file.

## Consistent export and bounded memory

Create the artifact while holding the existing sole-workspace writer lock and one queued SQL transaction/snapshot. Paginate tables by key with fixed row batches; never OFFSET through a changing view. Fetch one blob body at a time, validate bytes/hash and write one chunk, applying filesystem backpressure before fetching the next. Stream counts and chain. No `portable()`, all-blob SELECT, complete-file JSON.stringify, response.json(), browser Blob or base64 whole-library array is allowed. A SQL transaction may block local mutations for its duration; show that the backup is in progress, and release the queue on completion/failure/cancellation. Source domain rows are read only.

Startup/reopen integrity auditing is part of this same large-library acceptance requirement: iterate blob bodies one at a time; use SQL joins/counts for object/blob bijection, asset paths and normalized-high hash checks. Avoid all-byte materialization and nested array scans. Bound asset-row batches and use indexed SQL lookups. Keep all current corruption checks; an audit optimization must not weaken them.

## Artifact access and lifecycle

Server root is fixed `.local/workspace/exports/`. Create a UUID-named private temporary artifact with exclusive creation; publish by rename only after successful snapshot/footer write, flush and close. Only canonical UUID export IDs resolve artifacts; no caller-supplied paths. Recheck fixed-root containment and symlink/reparse protections on root/artifacts. Incomplete files are never downloadable. Keep live jobs protected from cleanup. On failure remove only that job's contained temporary artifact; on startup remove only demonstrably abandoned incomplete artifacts. Completed files persist until explicit protected deletion; no silent deletion of the user's sole backup.

A same-origin, token-protected small POST creates the export and returns only the export ID, exact file size and fixed download URL after completion (an asynchronous job/status endpoint is optional, not required). GET download enforces the existing loopback/Host/Origin/Fetch-Metadata read boundary, streams a completed server file with private/no-store/nosniff and Content-Disposition attachment. Never place a session token in a URL. Browser uses a normal download link/navigation so the browser's download manager streams to disk; it never fetches/parses the archive. Busy/failure states are visible. UI explains full domain contents, excluded collection files, and that v2 restore is an offline operation into an absent workspace. Legacy bounded v1 import can remain visibly separate.

## Offline restore and atomic visibility

CLI accepts a user-selected local file (not an HTTP path parameter) and requires the trusted fixed final `.local/workspace` directory to be absent. Any existing target, including an empty initialized workspace, fails; the user must independently preserve/relocate it before restore. Never remove/rename it automatically. Require the application stopped; use a separate fixed `.local` restore publication lock shared by restores and final target creation, and recheck target absence before publication. Workspace opening must respect that lock, preventing a concurrent new workspace from racing publication.

Read the bounded header first, then create a UUID stage only under fixed `.local/restore-staging/`, preserving header identity. Open a new migrated PGlite in that stage and validate ledger hash. Stream the complete file through bounded line decoding, parsing, byte/raster validation and per-table/key/count/chain checks. Load validated rows into private staging SQL tables with uniqueness constraints; blob bytes may be inserted into local_blobs in the final transaction as they arrive. Either use one transaction for staged import and final validation or a preparatory stage transaction followed by one final domain transaction. The staging database is disposable and never served. No complete-file array or full payload reconstruction.

Reuse version-1 validation semantics in bounded helpers: exact owner and table/column schemas; canonical base64, MIME/signature/decoding limits and hashes; positive calibrated dimensions; exact reservation/object/blob/asset closure and asset-kind checks; node/path-spec consistency; successor and Design references. Reject missing dependencies and prohibited cycles. Do not rely on the footer digest as proof of domain validity.

In one final SQL transaction follow existing trusted local import ordering: blobs, reservations with committed assets temporarily represented as pending, storage objects, assets through ordinary reservation/commit triggers, Parts in successor topological order, remaining table dependencies and Design sections. Do not disable/defer-away triggers, change session_replication_role, apply package SQL, or strip schema checks. For arbitrary successor UUID order, use a staging SQL readiness query/topological waves; lack of progress with remaining rows is an error. Revalidate each committed asset/reservation and each complete Design using existing validators. Preserve historical timestamps/revisions and SQL ownership. Compare restored ordered table/object/blob metadata digests/counts against streamed input digests using bounded scans, excluding only the deliberate transient reservation state before asset commit; compare final original reservation values. Do not invoke `portable()` to compare a large set.

Commit only after global closure/count/digest/SQL validation passes; then run bounded integrity audit, close/flush PGlite, and atomically rename the stage to the absent final path under the publication lock. Success is reported only after publication. Any pre-publication error leaves final target absent, closes PGlite and cleans only this contained stage. Crash leaves a recoverable/incomplete private stage, never a published partial workspace. Cleanup must validate absolute containment before recursive deletion and never touch catalog/parts/calibration directories. A target appearing concurrently causes failure without replacing it. Repeating restore against a published target fails safely; no costly whole-workspace equality comparison is required for offline v2. Version-1 same-identity idempotency semantics remain unchanged.

## Acceptance checks

Use isolated test roots only; no real SQL writes, registration, collection calls or Supabase. First prove preserved round-trip contents with archived/referenced Parts, successor graph, user state, source snapshots, nonempty Designs, all segment asset variants and exact image hashes/revisions. Exercise more than 50,000 logical rows and a valid set exceeding the old 90 MiB raw/128 MiB encoded limits with bounded repeated fixture images; assert bounded query batches/one-blob fetches and no aggregate portable() call. Reopen the restored disk-backed workspace and validate normal reads/Design retrieval.

Reject changed payload/hash, malformed/noncanonical base64, oversized line/blob/single row, duplicate IDs/path, missing/reordered/duplicate/truncated chunk, altered footer/count/identity/schema, unknown table/columns, foreign owner, missing image/asset/dependency, successor cycle, invalid Design and invalid reservation. Verify failed final SQL validation rolls back all imported domain rows. Inject disk-write failure, cancellation, post-chunk failure, final-transaction failure, crash-before-publication and publication race: source rows/registry unchanged, existing final target untouched, incomplete artifact undiscoverable. Test path traversal/link and unauthenticated/cross-origin export/download access. UI test verifies native download URL use and no whole-file parsing. Typecheck and focused existing local-workspace/route regressions complete verification. Large logical fixtures demonstrate engineering capacity only, not a claim that actual 16,681 Parts/strict47 or cloud migration were independently restored.
