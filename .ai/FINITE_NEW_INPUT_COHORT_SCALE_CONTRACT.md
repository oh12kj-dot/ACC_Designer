## 共通インターフェース

1. `finiteCohortCatalog` は追記専用のコホート索引。各 entry は連番 `cohortId`、schema version、unit/plan/registry/workspace の SHA または ID、scope と preparePlan ファイルの raw SHA、前 entry の SHA、作成時刻を持つ。**可変の状態は entry に置かず、別の進行 journal に置く**。既存 fixed7 は **legacy entry** として既存 scope hash を指すだけで、scope/manifest/既存 bridge の読み方と bytes を変更しない。新 entry は別の immutable scope/preparePlan ファイルを指す。索引追加は CAS/原子的書込で行い、重複 ID、既存 entry 改変、hash 連鎖切断を拒否する。catalog は候補の許可集合であり、採用証明ではない。
2. 新 `cohortScope` は `{version, cohortId, unitSha256, planSha256, registrySha256, rows}`。各 row は `draftId, sourceObjectSha256, primaryPhotoSha256, alternatePhotoSha256, galleryIndex, alternateUrl` と個別の source/BODY 意味・寸法・variant/写真対応審査への hash を固定する。unit001 の exact row と own gallery/capture/原 bytes、旧 ledger を毎回照合する。未登録・未 hold・販売可能・非 archived・未準備・既知失敗でないことを初回 preflight で確認する。Pearl、Delica、TOHO、Italy、品質、購入単位などの個別 legacy 判定を scope や category から推論して緩めない。意味や写真対応が立証できない row は scope に入れず理由付き保留とする。
3. `preparePlan` は**共有 preflight と加工の前**に凍結する。選んだ各 fresh original SHA ごとに、unit001/registry/gallery で関連する intended source の一覧を尽くし、各 source の採用予定・不適格・今回は対象外の区別と理由を記録する。採用予定の全 source について原寸写真、完成 BODY 全体の own 寸法、色/finish/variant、個体 pose、全候補 crop/BOX/seed を個別審査して固定し、`preparePlanSha256` を発行する。同じ写真の複数 source/BOX を初回 crop 前に列挙し終える。後から sibling を追加する場合は**未登録の別 fresh original** で新 cohort を組むのであり、公開済み共有写真を再開しない。写真単位の重複は許しても source 承認・Asset key・加工四画像承認は共有しない。
   - 新 cohort の `scope`/`preparePlan` は version 2 とし、row と intended association の `pixelPlanSha256` は `SHA256(JSON.stringify(pixelPlan))` を指す。`pixelPlan` は preparePlan の association に `{version:1,rendererSpec,attempts}` として実体を格納する。`rendererSpec` は**現行 v3 pixelSpec から `eligibility` だけを除いた同じ field/value/order**で、algorithm/runtime binding、原 SHA と URL、整数 crop、原寸、own BODY 寸法、無回転、preflight 前の sourceCrop/foreground review を含む。`attempts` は順序付きの全 `{crop,boxes,seeds}` 候補で、rendererSpec の crop と実行順を照合する。crop/BOX/seed 等、処理を変える入力は全てここで固定し、未列挙値を使えない。`eligibility`、preflight の read-set/SQL 証拠と時刻、加工後 review/画像 hash は含めない。scope と preparePlan は互いを循環参照しない既存の一方向 `preparePlan.scopeSha256` とし、両 raw SHA を catalog に固定する。
   - 共有 preflight が全 intended source に成功した後だけ、source ごとに `eligibilityBinding={version:1,cohortId,scopeSha256,preparePlanSha256,draftId,pixelPlanSha256,preflightReadSetSha256,eligibility,boundAt}` を一度だけ作る。`eligibility` は現行 `loadNewInputEligibility` が要求する reviewed/原・primary SHA/hold/登録/処理歴/own association/negative/SQL 等の証拠と `reviewedAt` を保持する。`boundAt` は追加記録時刻であり、凍結した `sourceCrop.reviewedAt` や original/correspondence/foreground review 時刻を書き換えない。binding の raw SHA を新 cohort の immutable manifest/出力 ledger に記録し、resume/保存で再照合する。新 cohort 専用の完成 `pixelSpec` は `{...pixelPlan.rendererSpec,eligibility:eligibilityBinding.eligibility}` という固定順の projection とし、**preflight 後、初回加工前**にその SHA と renderer/image key を固定する。attempts は pixelSpec に混入させず、加工実行時に preparePlan と照合する。`preparePlanSha256` は完成 `pixelSpec` や binding を参照しないので循環 SHA は生じない。legacy fixed7/採用 4 行の `pixelSpec`、spec、key、review、bytes は再計算しない。
4. `beginPrepareCohort(scopeSha, preparePlanSha)` は単一 writer が一度だけ実行し、既存 `loadNewInputEligibility` の unit/registry/plan/ledger、hold、sale policy、own capture、原 bytes、全 Part/Asset、全 prepared、正規化 negative/prefix を**全予定 source**について読み、preflight の read-set hash と SQL 行数・対象集合を固定する。既存 gate の証明項目を省略しない。同一 immutable cohort の準備中だけ、この初回 snapshot を source 間で共有する。後続 source の自分自身の binding/negative 判定は個別に行い、既にこの cohort が生成した prepared だけを「開始前の既準備」から区別する。外部追加・変更、同一写真の未列挙 source、別 cohort の出力、preparePlan 改変は fail closed。resume は同じ read-set/出力 ledger の一致を証明できる場合だけ許し、証明不能なら新規入力の処理を停止する。
5. `prepareCohort` は `createNewInputCohortPreparer()` を cohort で一度生成し全行で共有する。native key は原 SHA + 未回転整数 crop。初回機械失敗後は BOX、seed、review 時刻、版を替えても同じ crop を実行せず、元失敗と `processingExecuted=false` を記録する。永続 negative と履歴 prefix は単調追記、既存 prefix 改変不可。成功しただけでは採用しない。原寸 original/crop と high/medium/thumbnail を source ごとに別審査し、4 hash、spec、pixel/asset key、reviewer/time、preparedTransform、RGB 不変と alpha/輪郭/穴/影/白外枠を固定する。

### 別の未加工原写真で同じ source を後日扱う条件

`draftId` の catalog 全履歴での一意性は要求しない。新 scope に同じ `draftId` を入れる場合、先行 cohort の該当 row がすべて**終端失敗**であり、採用済み・保存済み・準備中・再開可能な row が一つもないことを、先行 `cohortId`/scope/preparePlan SHA、row、失敗理由、失敗した original SHA と crop signature、negative/履歴 prefix SHA、prepared 出力の有無と hash、live Part/Asset の source 0 件に結び付いた改変不能の closure receipt で証明する。進行 journal の `failed` 表示だけでは足りない。receipt は catalog の hash 連鎖 entry を変更せず、別の immutable 証拠として保存し、現在の journal は receipt SHA を参照する。失敗が crop 単位でも original 単位でも、**先行した exact original と全既試行 crop を二度と処理しない**。

新 row は `alternatePhotoSha256` がその source の全先行試行原 SHA と異なる、unit001/registry/gallery/capture に結び付く未加工 own 別原写真だけを使う。既登録 Asset、既 prepared、原単位 negative/hold、同時進行または他 cohort の scope にある写真は拒否し、旧失敗 crop の BOX/seed/review/版だけを替えた再試行を認めない。新 original の全関連 source を新 preparePlan で再列挙・個別審査し、共有写真の扱いは同一 cohort 内の上記例外だけを適用する。既登録 source への別原追加は不可。終端失敗の証拠が欠ける場合は同じ source の追加を保留する。

## 保存と再照合

新 scope の行を既存 v3 bridge の共通 validator に宣言的に追加する。`isCampaignBodySource` は **固定旧7の exact set ∪ 検証済み catalog scope の exact set** のみを返し、現在の `background-v3-scope.json` を広げない。recipe/process mode/manifest 形式を変える必要があれば新 schema と明示 migration を設け、既存 4 行の spec/key/bytes を再計算・再採用しない。family 別 bridge/renderer、意味判定の一括 allowlist は作らない。

保存直前に catalog/scope/preparePlan/manifest、unit/plan/registry/ledger、runtime/seed、旧・新 negative と履歴 prefix、sale/hold、prepared と画像四 hash、live SQL の Part/Asset/source/写真重複を再照合する。初回 preflight で他 cohort/既登録 Asset に使われた写真は拒否する。同一 cohort で**全 intended source を加工・審査・採用確定後**に保存した先行 source の写真だけは、scope/preparePlan/manifest に記録された source 集合、先行 Asset の exact key・原 hash・画像 hash・cohort ID が一致する場合に限り、後続 sibling の重複写真判定を通す。これ以外の既登録写真は常に拒否し、後続 sibling の own source 既登録/archived/重複は常に拒否する。写真例外は準備や再加工の許可に使えない。これが実装できなければ共有写真 cohort を保存せず保留する。

採用済みだけを既存 single writer に渡し、1 batch 250 行以下、25 行 checkpoint、各 commit 時に read-set と source 単位の再照合を行う。保存後は初回 created を別記録、正式 rerun `created=0`、各 Part/snapshot/Asset、原/high/medium/thumbnail の API bytes、購入価格・tag・一覧、穴/接続空、旧 Part/Asset/archive/registry/全 Design の保全を確認する。検証完了前は使用可能数に加算しない。gate の時間観測から速度や完了 ETA は約束しない。
