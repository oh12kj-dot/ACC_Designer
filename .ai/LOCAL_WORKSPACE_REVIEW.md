# Local workspace independent review

2026-10-05. Scope: local server, API access boundary, transport, backup UI and SQL migration gates. Requested model: gpt-6.1-sol / Medium; this agent has no separately exposed actual runtime model/effort confirmation. Static review; parent supplied passing test/typecheck/build results. No implementation edits made.

Status: changes required before local-workspace acceptance.

- **P1 — stale-lock recovery can admit two writers.** `src/server/localWorkspace.ts:27-28`: two processes can read the same dead PID; process A unlinks and acquires/writes a new lock; process B then unlinks A's live lock using its earlier observation and also acquires. Both open the same PGlite directory. Serialize stale recovery with a separate exclusive recovery lock and re-read/prove the current lock owner while holding it, or use a kernel-backed exclusive lock. Test concurrent recovery after hard termination, not just opening behind a live lock.
- **P1 — portable import bypasses domain gates.** `src/server/localWorkspace.ts:144-149` disables `upload_commit`, directly inserts Part rows, and validates only Design aggregates afterward. A valid-hash same-owner package with an unreferenced `geometry_kind='path'` Part and no path spec satisfies table checks, imports and passes byte/roundtrip checks, whereas migration 009 `save_part_successor` explicitly raises `PATH_SPEC_REQUIRED`. This can expose an unusable Part in the picker; preserving triggers is also an explicit contract invariant. Keep upload commit triggers enabled by staging historical committed reservations as pending and letting the trigger commit them; add a trusted restore validation gate covering every Part aggregate before acceptance, including path-spec requirements.
- **P2 — browser retries do not reuse idempotency keys.** `src/services/localWorkspaceClient.ts:12` generates a fresh key for every invocation. If create/save-Part commits but its response is lost, the retry creates another Design or unreferenced new Part; the server key table cannot recognize it. Uploads also have no matching-byte retry result (`localWorkspace.ts:104-105` errors on a duplicate path). Retain an operation key and exact payload across ambiguous failures and expose the retained operation to the UI/repository retry path; identical uploaded bytes at the same reserved path should return prior success, differing bytes must fail.
- **P2 — startup never audits persisted byte integrity.** `src/server/localWorkspace.ts:57-59` checks only schema owner and aggregate migration hash, then returns success. Missing/tampered bytes and missing owner identity in `auth.users` are checked only later (or not at all). A corrupted committed workspace can start and accept additional writes before a particular image is read. Audit owner/auth agreement, all committed referenced object/byte pairs and their hashes before exposing the workspace; fail visibly without reset. Add reopen corruption negatives.
- **P2 — supplied backup cannot initialize a replacement workspace.** `src/server/localWorkspace.ts:39,129` mints a fresh owner on a new PC/directory and unconditionally rejects the old backup owner; `WorkspaceBackup` exposes only ordinary import. The test bypasses this by manually writing `identity.json` before open. Users cannot recover through the advertised UI after losing the original workspace identity/directory. Add the contract's explicit empty-workspace restore operation that validates a package before atomically installing its retained identity, and preserve rejection against an existing different-owner workspace.
- **P2 — full-library export is bounded only after materialization.** `src/server/localWorkspace.ts:120-125` loads every blob, base64-encodes all bytes and stringifies the entire database before testing the 128 MiB limit. A library larger than this can exhaust server memory, and no Part/Design subset export exists. Preflight counts/byte totals and offer a dependency-closed Part batch or Design package with an explicit limited result. Do not describe this as portable whole-library migration support.

Additional limits: import accepts noncanonical base64 via `Buffer.from(...,'base64')`; local token is cached for the browser lifetime, so server restart rejects subsequent mutation requests until the page reloads; schema version lookup does not reject additional unsupported version rows. Address within the relevant fixes or document unsupported behavior explicitly.

Calibration boundary remains sound only as an inventory audit: `scripts/audit-calibration.mjs` does not run provider detail enrichment or produce measurement-to-pixel certificates. The 27,046 blocked entries and absence of promoted real Parts must remain explicit; backend tests cannot establish full-variant readiness or physical ±3% accuracy.

## Bounded blocking-finding confirmation

- **Stale-lock race resolved in inspected code.** Recovery now exclusively claims `recovery.lock`, re-reads the writer PID and verifies its exit while holding that claim before unlink/reacquisition. A contender cannot act on the earlier dead-PID observation after another process has installed its live lock. The new two-contender regression asserts exactly one successful opener. Parent reports eight persistence tests passing; this follow-up inspected code/test definitions and did not repeat the suite.
- **Missing-path-spec import resolved in inspected code.** Every imported Part is checked for its main asset and required/forbidden path-spec relationship before blob inserts. The regression changes genuine package Parts to path geometry, recomputes the package hash, expects `PATH_SPEC_REQUIRED` and confirms the target remains empty. The original concrete malformed-package acceptance is closed.

This was explicitly included in the original import finding and contradicts the approved restore contract. Restore reservations for imported assets initially as pending, set trusted owner context before asset insertion and allow the existing commit trigger to produce their committed state; retain final package equality. Closing the demonstrated missing-spec bug does not establish this contract invariant.

These narrow confirmations do not establish full local-workspace contract acceptance, cloud migration or real-variant calibration readiness.
